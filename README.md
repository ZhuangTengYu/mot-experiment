# 多目标追踪浏览器实验

使用 Canvas 和 JavaScript 实现的多目标追踪任务，可作为静态网页发布。页面不依赖 CDN，无需构建工具或后端服务，受试者无需注册账号。

## 发布到 GitHub Pages

将下列文件直接放在仓库根目录，保持文件名和相对位置：

- `index.html`
- `app.js`
- `styles.css`
- `mot-core.js`
- `.nojekyll`
- `README.md`

使用上传包时，先解压，再上传里面的文件；不要上传 ZIP 或外层文件夹。不要上传测试脚本、实验报告、个人信息和被试数据。

1. 在仓库 Code 页选择 **Add file → Upload files**，上传上述文件并提交到 `main`。
2. 确认根目录能直接看到 `index.html`。
3. 进入 **Settings → Pages**，将 Source 设为 **Deploy from a branch**，Branch 选 `main`，目录选 **/(root)**，点击 **Save**。
4. 等部署完成后，使用 Pages 页给出的站点链接打开，先点击 **先试用流程（非实测）** 核对显示、操作与下载。仅看到仓库文件不表示网页已经发布成功。

流程演示使用 1 次练习和 4 次正式阶段演示试次，提示与运动时间缩短，记录标为演示，不能用作实测。真正的正式测试固定为 4 次练习、40 次正式试次，目标闪烁 3 秒、追踪 6 秒。

若打不开，先检查 Pages 或 Actions 的部署状态，再核对分支、根目录和文件名大小写。更新文件并提交后，等待新部署完成，再刷新核对。

## 测试条件与任务

使用电脑上的 Chrome 或 Edge，浏览器缩放设为 100%，尽量全屏。网页可视区域至少为 1100×740 CSS 像素；不接受手机测试。

三名受试者分别使用分配的匿名编号 `P01`、`P02`、`P03`，使用同一版本和相同参数，初始速度统一为默认的 160 像素/秒。先完成 4 次练习，再完成 40 次正式试次。若一批需要三名受试者，三人都应在同一网页版本完成，不用本地 PsychoPy 数据补入网页组。

每次出现 8 个球，目标数为 3–6。目标闪烁 3 秒后，8 个球恢复相同外观并运动 6 秒。停止后用鼠标点选或取消，恰选够指定数量再按空格提交。

测试中不要切换标签或窗口、改变浏览器缩放或调整窗口尺寸。标签切换、窗口失焦、缩放或尺寸变化会中止会话，需要重新完整测试。自动进度备份和可下载的中止记录用于保留已完成部分，不能作为正式完成数据导入。

## 下载结果

全部完成后点击 **下载完整结果 JSON**，确认文件已经保存，保留原文件名及内容，将 JSON 原文件私下发给主试。CSV 可选，提交结果只需完整 JSON。

网页没有自动数据回传。GitHub Pages 不会替主试收集结果；不要把被试 JSON、CSV 或个人信息提交到公开仓库或公开 Issues。

主试在自己的电脑上使用配套工具处理文件，顺序为：

1. 将完整 JSON 放入 `web_inbox`。
2. 运行 `导入网页数据.bat`，校验并导入独立的 `data_web`。
3. 运行 `分析网页数据.bat`，将统计和图表写入 `output_web`。
4. 运行 `更新网页报告.bat`，生成独立的 `实验报告3_工作记忆_浏览器实测.docx`，再核实真实环境、日期、结果和讨论，并检查页码与排版。

这些工具只在主试本机运行，不要上传网页仓库。网页流程不会自动覆盖本地 PsychoPy 的 `data`、`output` 或原有本地实验报告。同一批数据应使用同一呈现引擎，不混合浏览器版与本地 PsychoPy 数据；处理网页数据时使用上述网页版工具，不使用原来的本地分析和更新入口。

## 实现与报告表述

本网页以 Canvas 和 JavaScript 移植本地 PsychoPy 程序的实验逻辑和运动算法，实际在浏览器中呈现，未使用 PsychoJS。网页报告更新工具会按 `browser_canvas` 呈现引擎填写浏览器说明，主试仍需补充并核实实际设备、浏览器、采集日期和结果讨论。发布网页本身不会修改原有报告。未经课堂要求确认，不应将本实现描述为使用 PsychoPy 或 PsychoJS 呈现。
